Reinforcement Learning as MDP

How an environment transitions from one state to the next using what is known as the transition function

Reinforcement Learning as MDP

  • A Markov Decision Process (MDP) is simply a way to describe the repeated interaction between an agent and an environment.
  • At each step:

\[ \boxed{ \text{Current State} \rightarrow \text{Action} \rightarrow \text{Reward + Next State} } \]

  • For an RL agent:
    • State \(s_t \in \mathcal{S}\): What does the environment look like right now?
      • \(\mathcal{S}\) is the state space.
    • Action \(a_t \in \mathcal{A}\): What should the agent do?
      • \(\mathcal{A}\) is the action space.
    • Next state \(s_{t+1}\): What happened after the action, \(a_t\) is being acted on the environment?
    • Reward \(r_{t} = \mathcal{R}(s_t, a_t, s_{t+1}\): How good was that action?
      • \(\mathcal{R}\) is the reward function.

So one interaction looks like:

\[ s_t \overset{a_t}{\longrightarrow} (r_{t},s_{t+1}) \]

  • In the Python codes previously presented to you captures all of the above:
#Running episode after episode
for episode in range(max_episodes):
  #Reset environment and observe the start state
  observation, info = env.reset()

  while not (terminated or truncated):
    #Select an action based on current policy
    action = policy(observation)
    
    #Perform that selected action on the environment
    next_observation, reward, terminated, truncated, info = env.step(action)

    #moving to next time-stemp
    observation = next_observation
  • action: \(a_t\)
  • observation: \(s_t\)
  • reward: \(r_t\)
  • next_observation: \(s_{t+1}\)
  • state transition function, \(P(s_{t+1}|\boxed{(s_0,a_0), (s_1,a_1), \cdots (s_t,a_t)})\)
    • Or, simply \(P(s_{t+1}|(s_t,a_t))\) (Thanks to Markov Property)
  • The agent gives Gymnasium an action, and the environment returns the next state and reward.

MDP and POMDP

  • Two definitions of state!
    1. (Observed state, \(s_t\)): The state is what is produced by an environment and observed by an agent.
    2. (Internal state, \(s^{\text{int}}_t\)): the state what is used by the state transition function, \(P\).
      • \(s_{t+1} \sim P(s_{t+1}| (s_t,a_t))\)
  • In MDP, \(s_t = s^{\text{int}}_t\)
    • the observed state is identical to the environment’s internal state.
    • That is, the same state information which is used to transition an environment into the next state is also made available to an agent.
  • But, this is not always the case.
  • The observed state may differ from the environment’s internal state, \(s_t \neq s^{\text{int}}_t\)
    • The environment is described as a partially observable MDP (POMDP) because the state \(s_t\) exposed to the agent only contains partial information about the state of the environment.

POMDP

  • Think of a robot trying to find the exit in a dark hallway.

  • Imagine a hallway with three locations:

Left — Middle — Right

  • The exit is at Right. The robot can choose:

  • Move Left

  • Move Right

In a normal MDP, the robot would know exactly where it is: “I am in the Middle.”

In a POMDP, the robot cannot directly see its true location. Its sensor is imperfect. It might only observe something like:

“I think I am near a wall.”

But both the Left and Right locations have walls, so this observation does not tell the robot exactly where it is.

Suppose the robot starts with this belief:

  • 20% chance it is at Left
  • 60% chance it is at Middle
  • 20% chance it is at Right

It moves right and then its sensor says:

“Wall detected.”

Now the robot reasons: “Since I moved right and now I detect a wall, I am probably at the Right end.”

So its updated belief might become:

  • Left: 5%
  • Middle: 15%
  • Right: 80%

The important idea is that the agent acts based not only on the current observation, but on its belief about the hidden state.

MDP vs POMDP

MDP: “I know where I am. What should I do?”

POMDP: “I am not completely sure where I am. Based on what I have observed so far, what should I do?”

For the robot example:

POMDP component Example
Hidden state \(s\) Robot’s actual location
Action \(a\) Move left or right
Observation \(o\) Sensor says “wall” or “no wall”
Reward \(r\) +10 for reaching the exit
Transition How movement changes location
Observation model How likely the sensor reading is at each location
Belief \(b(s)\) Robot’s probability of being at each location

The key new ingredient compared with an MDP is the observation and the belief state.

A POMDP is an MDP where the agent cannot directly observe the true state of the environment, so it must estimate the state from incomplete or noisy observations.**

  • A real-world analogy is driving in heavy fog:
    • you still decide whether to accelerate, brake, or turn, but you cannot perfectly observe everything around your car.
  • Some of the environments we find in gymnasium are not perfect MDPs, although we might model assuming them to be MDPs.
    • E.g., In Atari environment, the observed state \(s_t\) is a single RGB image which conveys information about object positions, lives, etc., but not object velocities.
    • Velocities would be included in the environment’s internal state since they are required to determine the next state given an action.
    • In these cases, to achieve good performance, we will have to modify \(s_t\) to include more information.
  • Many interesting real-world problems are inherently POMDPs for many reasons, including sensor or data limitations, model error, and environment noise.

MDP control loop

Given an env (environment) and an agent

#Running one episode after another episode, and so on ...
for episode in [ 0, ..., MAX_EPISODES ]:

  #Reset environment and observe the start state
  state = env.reset()
  agent.reset()

  #run episodes for T time-steps, starting 0, 1, ..., T
  for t in [0, ..., T]:
    #Select an action based on current policy
    action = agent.policy(state)
    
    #Perform that selected action on the environment
    state, reward = env.step(action)

    #Improve policy
    agent.update_policy(action, state, reward)

    #Check if the episode terminated before final time-step, T
    if env.done():
      break

Learnable functions in MDP based Reinforcement Learning

What should the agent learn?

  • We have seen that an agent can learn an action-producing function known as a policy.
  • However, there are other properties of an environment that can be useful to an agent.
  • In particular, there are three primary functions to learn in reinforcement learning:
    1. A policy, \(\pi(s)\) function , that maps a state, \(s\) into an action, \(a\): \(a \sim \pi(s)\)
      • Given the MDP control loop, an agent must produce an action at every time step after observing a state \(s\).
      • A policy is fundamental to this control loop, since it generates the actions to make it run.
      • A policy can be stochastic. That is, it may probabilistically output different actions for the same state.
        • We can write this as \(\pi(a|s)\) to denote the probability of an action \(a\) given a state \(s\). An action sampled from a policy is written as \(a \sim \pi(s)\).
    2. A value, \(V^\pi(s)\) function, or \(Q^\pi(s,a)\) function to estimate expected future return \(\mathbb{E}_\tau [R(\tau)]\)
      • The value functions provide information about the objective of the agent.
      • They help an agent understand how good the states and available actions are in terms of the expected future return.
      • Here, a trajectory from an episode, \(\tau = (s_0, a_0, r_0), \cdots, (s_T, a_T, r_T)\) \[ V^\pi(s) = \mathbb{E}_{s_0=s, \tau \sim \pi}\left[\sum_{t=0}^T \gamma^t r_t \right] \]
      • \(V^\pi\) measures the expected return from being in state \(s\), assuming the agent continues to act according to its current policy, \(\pi\).
        • The return, \(R(\tau) = \sum_{t=0}^T\gamma^t r_t\) is measured from current state, \(s\) to the end of the episode.
        • Please note: \(R(\tau)\) is a forward-looking measure, since all rewards received before state \(s\) are ignored. \[ Q^\pi(s,a) = \mathbb{E}_{s_0=s, a_0=a,\tau \sim \pi}\left[\sum_{t=0}^T \gamma^t r_t \right] \]
      • The \(Q\)-value function, \(Q^\pi(s,a)\) evaluates how good or bad a state-action pair is.
        • it measures the expected return from taking action \(a\) in state \(s\) assuming that the agent continues to act according to its current policy, \(\pi\).
          • In the same manner as \(V^\pi(s)\), the return is measured from the current state \(s\) to the end of an episode.
        • It is also a forward-looking measure, since all rewards received before state \(s\) are ignored.
    3. The environment model, \(P(s'|s,a)\), which is pretty much the transition function that provides information about the environment.
      • If an agent learns this function, it is then able to predict the next state \(s'\) that the environment will transition into after taking action \(a\) in state \(s\).
      • By applying the learned transition function, an agent can “imagine” the consequences of its actions without actually touching the environment.
      • It can then use this information to plan good actions, i.e., devise its policy.

Types of Reinforcement Learning Algorithms

In the previous slide, we have just seen the three primary learnable functions in reinforcement learning: (1) policy, (2) value, and (3) model

  • Correspondingly, there are three major families of reinforcement learning algorithms:
    1. Policy-based algorithms
    2. Value-based algorithms
    3. Model-based algorithms
  • Moreover, there are also combined methods in which agents learn more than one of these functions.
    • For instance: a policy and a value function, or a value function and a model.

Policy-based Algorithms

Algorithms in this family learn a policy \(\pi\).

  • Good policies should generate actions which produce trajectories, \(\tau\) that maximize an agent’s objective, \(J(\tau) = \mathbb{E}_{\tau \sim \pi} \left[ \sum_{t=0}^T \gamma^t r_t\right]\)
    • if an agent needs to act in an environment, it learns a policy (intuitively speaking, right?).
      • What constitutes a good action at a given moment depends on the state,
      • So a policy function, \(\pi\) takes a state \(s\) as input to produce an action \(a \sim \pi(s)\)
  • REINFORCE, Vanilla Policy Gradient (VPG), Natural Policy Gradient (NPG) are policy-based algorithms.
  • Pros:
    • The algorithms can be applied to problems with any type of actions: discrete, continuous, or a mixture (multiactions).
    • They also directly optimize for the thing an agent cares most about—the objective \(J(\tau)\).
    • This class of methods is guaranteed to converge to a locally optimal policy.
  • Cons:
    • The algoriothms have high variance
    • They are sample-inefficient

Value-based Algorothms

An agent learns either \(V^\pi(s)\) or \(Q^\pi(s,a)\).

  • It uses the learned value function to evaluate \((s, a)\) pairs and generate a policy.
    • For example, an agent’s policy could be to always select the action \(a\) in state \(s\) with the highest estimated \(Q^\pi(s,a)\).
  • Learning \(Q^\pi(s,a)\) is far more common than \(V^\pi(s)\) for pure value-based approaches because it is easier to convert into a policy.
    • \(Q^\pi(s,a)\) contains information about paired states and actions whereas \(V^\pi(s)\) just contains information about states.
  • SARSA, Deep Q-Networks (DQN), Double DQN, DQN with Prioritized Experience Replay (PER), QT-OPT algorithms belong to this category of RL algorithms.
  • Pros:
    • Valuse-based methods are typically more sample-efficient than policy-based algorithms.
      • This is because they have lower variance and make better use of data gathered from the environment.
  • Cons:
    • There are no guarantees that these algorithms will converge to an optimum.
    • In their standard formulation, they are also only applicable to environments with discrete action spaces. This has historically been a major limitation.
      • Recent advances, such as QT-OPT can be effectively applied to environments with continuous action spaces.

Model-based Algorithms

Algorithms in this family either learn a model of an environment’s transition dynamics or make use of a known dynamics model.

  • Once an agent has a model of the environment, \(P(s'|s,a)\), it can “imagine” what will happen in the future by predicting the trajectory for a few time steps.
  • If the environment is in state \(s\), an agent can estimate how the state will change if it makes a sequence of actions \(a_1, a_2, \cdots, a_n\) by repeatedly applying \(P(s'|s,a)\), all without actually producing an action to change the environment.
    • Hence, the predicted trajectory occurs in the agent’s “head” using a model.
  • An agent can complete many different trajectory predictions with different actions sequences, then examine these options to decide on the best action a to actually take.
  • Purely model-based approaches are most commonly applied to games with a target state, such as winning or losing in a game of chess, or navigation tasks with a goal state \(s^*\).
    • This is because their transition functions do not model any rewards.
  • Monte Carlo Tree Search (MCTS), iterative Linear Quadratic Regulators (iLQR) belong to this category of RL methods.
  • Pros:
    • They are very appealing because a perfect model endows an agent with foresight.
    • it can play out scenarios and understand the consequences of its actions without having to actually act in an environment.
    • This can be a significant advantage in situations where it is very time-consuming or expensive to gather experiences from the environment—for example, in robotics.
    • Compared to policy-based or value-based methods, these algorithms also tend to require many fewer samples of data to learn good policies since having a model enables an agent to supplement its actual experiences with imagined ones.
  • Cons:
    • This kind of models are very hard to come by.
    • Many environments are stochastic, and their transition dynamics are not known – in these cases, the model must be learned.
    • an environment with a large state space and action space can be very difficult to model
    • models are only useful when they can accurately predict the transitions of an environment many steps into the future.
      • Depending on the accuracy of the model, prediction errors may compound for every time step and quickly grow to make the model unreliable.
    • The lack of good models is currently a major limitation for the applicability of model-based approaches.
      • However, model-based methods can be very powerful. When they work, they are often 1 or 2 orders of magnitude more sample-efficient than model-free methods.
  • Funny thing!!
    • The discussion on models gets us into a discussion about another two broad categories of algorithms:
      • Model-based Reinforcement Learning algorithm:
        • It is simply any algorithm that makes use of the transition dynamics of an environment, whether learned or known in advance.
      • Model-free Reinforcement Learning algorithm:
        • It doesn’t explicitly make use of the environment transition dynamics.

Combined Methods

Given the strengths and weaknesses of each of the three methods discussed so far, it is natural to try to combine them to get the best of each.

  • One widely used group of algorithms learns a policy and a value function.
    • These are aptly named Actor-Critic algorithms because –
      • here, the policy acts and the value function critiques the actions.
  • During training, a learned value function can provide a more informative feedback signal to a policy than the sequence of rewards available from the environment.
  • The policy learns using information provided by the learned value function. The policy is then used to generate actions, as in policy-based methods.
  • Trust Region Policy Optimization (TRPO), Proximal Policy Optimization (PPO), Deep Deterministic Policy Gradients (DDPG), Soft Actor-Critic (SAC) are combined methods.
    • Of these, PPO is currently the most widely used algorithm.
  • Algorithms may also use a model of the environment transition dynamics in combination with a value function and/or a policy.
    • AlphaGo combines MCTS with learning \(V^\pi\).
    • Dyna-Q combines model-based and \(Q\) value-based methods.

On-policy vs Off-policy algorithms

  • On-Policy methods:
    • it learns on the current policy, that is, training can only utilize data generated from the current policy \(\pi\).
    • This implies that as training iterates through versions of policies, \(\pi_1, \pi_2, \pi_3, \cdots\),
      • each training iteration it only uses the current policy at that time to generate training data.
      • As a result, all the data must be discarded after training, since it becomes unusable.
      • This makes on-policy methods sample-inefficient—they require more training data.
    • REINFORCE, SARSA, Actor-Critic methods, PPO are on-policy methods
  • Off-Policy methods:
    • this methods do not have the requirement to use current policy or a specific policy from a specific iteration.
      • It implies that any data collected can be reused in training.
      • That’s why off-policy methods are more sample-efficient,
      • but this may require much more memory to store the data.
    • DQN is an off-policy method.

Deep Learning in Reinforcement Learning

  • Deep neural networks excel at complex nonlinear function approximation.
    • They are structured as alternating layers of parameters and nonlinear activation functions,
    • Neural networks learn functions, which are simply mappings of inputs to outputs.
    • They perform sequential computations on an input to produce an output; this process is known as a forward pass.
    • A function is represented by a particular set of values of the of parameters \(\theta\) of a network;
      • we say that “the function is parametrized by \(\theta\).”
    • Different values of the parameters correspond to different functions.

Basics of Neural Network based Learning

  • To learn a function, we need a method to acquire or generate a sufficiently representative dataset of inputs and a way of evaluating the outputs that a network produces.
  • Evaluating the outputs can mean one of two things:
    • The first way is to generate the “correct” output, or target value, for each input and define a loss function which measures the error between the target and the network-predicted output. This loss should be minimized.
    • The second way is to directly provide feedback for each input in the form of a scalar value, such as a reward or return. This scalar represents how good or bad the network’s output is, and it should be maximized (for goodness). When negated, this value can also be considered a loss function to be minimized.
  • Given a loss function which evaluates a network’s outputs, it is possible to change the values of a network’s parameters to minimize the loss and improve performance.
    • This is known as gradient descent because we change the parameters in the direction of steepest descent on the loss surface in search of a global minimum.
  • Changing the parameters of a network to minimize a loss is also known as training a neural network.
  • Suppose the function \(f(x)\) being learned is parametrized with network weights \(\theta\) as \(f(x; \theta)\), with \(x, y\) as the input-output data, and let \(\mathcal{L}(f(x; \theta), y)\) be the predefined loss function, the training the network steps can be summarized below:
  1. Sample a random batch \((x, y)\) from dataset, where the batch size is significantly smaller than the total size of the dataset.
  2. Compute a forward pass with the network using the inputs \(x\) to produce predicted outputs, \(\hat{y} = f(x; \theta)\).
  3. Compute the loss \(L(\hat{y}, y)\) using \(\hat{y}\) predicted by the network and \(y\) from the sampled batch.
  4. Calculate the gradient (partial derivative) of the loss \(\nabla_\theta L\) with respect to the parameters of the network. Modern neural network libraries such as PyTorch or TensorFlow handle this automatically using the backpropagation algorithm (a.k.a. “autograd”).
  5. Use an optimizer to update the network parameters using the gradient. For example, a stochastic gradient descent (SGD) optimizer makes the following update: \(\theta_{\text{new}}= \theta_{\text{old}} − \alpha \nabla_\theta L\), where \(\alpha\) is a scalar learning rate.

This training step is repeated until the network’s outputs stop changing or the loss has minimized and plateaued which potentially indicates that the network has converged.

How Neural networks are adopted in RL

  • In reinforcement learning, neither the network inputs \(x\) nor the correct outputs \(y\) are given in advance.
    • Instead, these values are obtained through agent interactions with an environment — from the states and rewards it observes.
  • The difficulties in data generation and evaluation are due to the fact that the functions that we try to learn are tightly coupled with the MDP loop.
    • The data exchange between an agent and an environment is interactive and the process is inherently limited by the time needed for an agent to act and for an environment to transition.
    • There is no shortcut to generating data for training—an agent has to experience every time step.
    • The data collection and training cycle runs repeatedly, with every training step (potentially) waiting for new data to be collected.
  • Since the current state of an environment and the actions an agent takes affect the future states it experiences, states and rewards at any given point in time are not independent of states and rewards at previous time steps.
    • That is unlike traditional Feedforward neural network modeling.
    • This violates an assumption of gradient descent—that data is identically and independently distributed (i.i.d.)
  • The speed at which a network converges and the quality of the final result can be adversely affected.
    • Significant research effort has gone into minimizing this effect.
  • Despite these challenges, deep learning is a powerful technique for function approximation.
    • It is worth pursuing to overcome the difficulties of applying it to reinforcement learning, as the benefits greatly outweigh the challenge remediation costs.
