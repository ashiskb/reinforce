1. A Quick REINFORCE Recap

1.1 Goal of REINFORCE

Before introducing something new, I would like to remind you what REINFORCE is actually doing, from the perspective of the CartPole-v1 agent.

We have a policy parameterized by an artificial neural network:

\[ \pi_\theta(a|s) \]

Given a state \(s\), the network outputs probabilities of possible actions.

For example, in CartPole-v1:

\[ \pi_\theta(a|s) = [0.25,\;0.75] \]

might mean:

  • probability of moving left = 0.25

  • probability of moving right = 0.75

  • The agent samples an action from this distribution. This means:

    • If the agent appears to be in the same state (\(s\)) 100 times,
      • it will choose to move left approximately 25 times, and to move right 75 times.

1.2 The basic REINFORCE idea

Suppose the agent takes an action \(a_t\) in state \(s_t\).

Later, it observes a return:

\[ G_t = r_t+\gamma r_{t+1}+\gamma^2r_{t+2}+\cdots \]

REINFORCE updates the policy using:

\[ \nabla_\theta J(\theta) \approx G_t \nabla_\theta \log\pi_\theta(a_t|s_t) \]

A useful interpretation is:

Increase the probability of actions associated with good outcomes, and decrease the probability of actions associated with bad outcomes.

1.3 An Example

Suppose:

\[ \pi(\text{Right}|s)=0.60 \]

The agent chooses Right, and eventually receives a large positive return.

The policy should learn:

“Taking Right in a situation like this seems useful. Make it slightly more likely next time.”

If the return is poor, the opposite happens.

1.4 A somewhat short recap of the REINFORCE Loss Function

The REINFORCE loss is commonly written as

\[ L(\theta) = -\sum_t G_t \log \pi_\theta(a_t|s_t) \]

At first glance, this can look complicated.

But the idea behind it is actually very simple:

If an action leads to a good outcome, make that action more likely next time.

If an action leads to a bad outcome, make that action less likely next time.

Everything in the loss function exists to accomplish that goal.

1.4.1. Start with the Policy

Suppose our agent is in a state \(s\).

The policy network outputs probabilities for possible actions.

For CartPole-v1:

\[ \pi_\theta(a|s) = [0.25,0.75] \]

which means:

\[ P(\text{Left})=0.25 \]

\[ P(\text{Right})=0.75 \]

Suppose the agent samples:

\[ a=\text{Right} \]

The policy tells us:

\[ \pi_\theta(\text{Right}|s)=0.75 \]

Now the important question is:

Was choosing Right a good decision?

We cannot answer that just from the probability.

We need to see what happened afterward.

1.4.2. The Discounted Future Return Tells Us How Good the Outcome Was

After taking action \(a_t\), the agent receives rewards.

The return is

\[ G_t = r_t+\gamma r_{t+1} +\gamma^2r_{t+2} +\cdots \]

Think of \(G_t\) as a score assigned to the action.

Large positive return

\[ G_t=50 \]

means roughly:

“The action was followed by a good outcome.”

Small or negative return

\[ G_t=-10 \]

means:

“The action was followed by a poor outcome.”

So now we have:

state
  ↓
action
  ↓
future rewards
  ↓
return G
  ↓
How much should we encourage
or discourage this action?

1.4.3. Why Do We Use the Probability of the Selected Action?

Suppose the policy produced:

\[ P(\text{Left})=0.25 \]

\[ P(\text{Right})=0.75 \]

and the agent selected Right.

If Right resulted in a good outcome, we want:

\[ P(\text{Right}|s) \]

to increase.

We therefore need a mathematical quantity connected to the probability of the action that was actually selected.

That gives us:

\[ \pi_\theta(a_t|s_t) \]

1.4.4. Why Logarithm?

REINFORCE does not directly use:

\[ \pi_\theta(a_t|s_t) \]

Instead, it uses:

\[ \log \pi_\theta(a_t|s_t) \]

Why?

The logarithm is not just a numerical convenience; it appears naturally when we derive the policy gradient.

The key identity is:

\[ \boxed{ \nabla_\theta \pi_\theta(a|s) = \pi_\theta(a|s) \nabla_\theta \log \pi_\theta(a|s) } \]

or equivalently,

\[ \boxed{ \nabla_\theta \log \pi_\theta(a|s) = \frac{\nabla_\theta \pi_\theta(a|s)} {\pi_\theta(a|s)} } \]

This is often called the log-derivative trick or likelihood-ratio trick.

1.4.4.1. Start from the objective

In reinforcement learning, we want to maximize expected return:

\[ J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta} [R(\tau)] \]

where \(\tau\) is a trajectory:

\[ \tau=(s_0,a_0,s_1,a_1,\ldots) \]

and \(R(\tau)\) is its total return.

Written explicitly:

\[ J(\theta) = \sum_\tau P_\theta(\tau)R(\tau) \]

Now differentiate:

\[ \nabla_\theta J(\theta) = \sum_\tau \nabla_\theta P_\theta(\tau)R(\tau) \]

The difficulty is that we have:

\[ \nabla_\theta P_\theta(\tau) \]

inside the sum.

The log trick lets us rewrite it.

Because

\[ \nabla_\theta \log P_\theta(\tau) = \frac{\nabla_\theta P_\theta(\tau)} {P_\theta(\tau)} \]

we get:

\[ \nabla_\theta P_\theta(\tau) = P_\theta(\tau) \nabla_\theta\log P_\theta(\tau) \]

Therefore,

\[ \nabla_\theta J(\theta) = \sum_\tau P_\theta(\tau) R(\tau) \nabla_\theta\log P_\theta(\tau) \]

which becomes an expectation:

\[ \boxed{ \nabla_\theta J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta} \left[ R(\tau) \nabla_\theta \log P_\theta(\tau) \right] } \]

This is extremely useful because now we can estimate the gradient simply by sampling trajectories.

That is the mathematical heart of REINFORCE.

1.4.4.2. Why does the trajectory probability become a sum?

The probability of a trajectory contains a product of policy probabilities:

\[ P_\theta(\tau) = p(s_0) \prod_t \pi_\theta(a_t|s_t) P(s_{t+1}|s_t,a_t) \]

The environment transition probabilities do not depend on \(\theta\), so when differentiating with respect to the policy parameters, only

\[ \prod_t \pi_\theta(a_t|s_t) \]

matters.

Now apply the logarithm:

\[ \log \left( \prod_t \pi_\theta(a_t|s_t) \right) \]

Using

\[ \log(xy)=\log x+\log y \]

we obtain:

\[ \boxed{ \log P_\theta(\tau) = \text{constant} + \sum_t \log\pi_\theta(a_t|s_t) } \]

Therefore,

\[ \nabla_\theta \log P_\theta(\tau) = \sum_t \nabla_\theta \log\pi_\theta(a_t|s_t) \]

This is another major reason the logarithm is useful:

It turns a product of probabilities across a trajectory into a sum.

That makes differentiation much easier.

1.4.4.3. From this to the REINFORCE update

Substituting back gives:

\[ \nabla_\theta J(\theta) = \mathbb{E} \left[ R(\tau) \sum_t \nabla_\theta \log \pi_\theta(a_t|s_t) \right] \]

A more refined version uses the return from time (t):

\[ \boxed{ \nabla_\theta J(\theta) = \mathbb{E} \left[ \sum_t G_t \nabla_\theta \log \pi_\theta(a_t|s_t) \right] } \]

This is the REINFORCE policy-gradient equation.

So the \(\log\) is not arbitrarily inserted into the loss.

It appears directly from differentiating the expected return.

1.4.4.4. Why not just use \(\pi_\theta(a_t|s_t)\)?

Suppose we tried something like:

\[ G_t\pi_\theta(a_t|s_t) \]

Its gradient would be:

\[ G_t\nabla_\theta\pi_\theta(a_t|s_t) \]

But this does not give us the convenient expectation form:

\[ P(\tau)\nabla\log P(\tau) \]

that lets us estimate the gradient using sampled trajectories.

The log derivative effectively converts

\[ \nabla P \]

into:

\[ P\nabla\log P \]

and the \(P\) becomes exactly the probability distribution we are sampling from.

That is what allows Monte Carlo estimation.

1.4.4.5. A particularly intuitive interpretation

Consider:

\[ \nabla_\theta \log\pi_\theta(a|s) \]

Because

\[ \nabla_\theta\log\pi = \frac{1}{\pi} \nabla_\theta\pi \]

this is a relative change in probability, rather than an absolute change.

Roughly:

\[ \nabla\log\pi \sim \frac{\text{change in probability}} {\text{current probability}} \]

That matters.

For example, changing a probability from

\[ 0.01\rightarrow0.02 \]

is a huge relative change: it doubled.

But changing

\[ 0.81\rightarrow0.82 \]

is a much smaller relative change.

The log naturally captures this relative sensitivity.

1.4.4.6. Connection to maximum likelihood

Suppose supervised learning tells us:

Action \(a\) is the correct action for state \(s\).

Maximum likelihood would maximize:

\[ \log\pi_\theta(a|s) \]

or minimize:

\[ -\log\pi_\theta(a|s) \]

REINFORCE looks very similar:

\[ \boxed{ L = -G_t \log\pi_\theta(a_t|s_t) } \]

You can interpret it as a kind of reward-weighted maximum likelihood.

If:

\[ G_t \gg 0 \]

the selected action behaves almost like a strongly reinforced training label.

If the return is poor, that action receives much less support—or, with negative advantage/return, can be actively discouraged.

This analogy may seem like a bridge for you if you already know classification.

1.4.4.7. The three mathematical reasons to remember

Let’s summarize why the logarithm is used in the definition of REINFORCE loss function.

Reason 1: The log-derivative identity

\[ \boxed{ \nabla_\theta P = P\nabla_\theta\log P } \]

This lets us rewrite the gradient in a form that can be estimated from samples. (Monte-Carlo Estimation)

Reason 2: Log turns products into sums

Trajectory probabilities contain:

\[ \prod_t \pi(a_t|s_t) \]

Taking logs gives:

\[ \sum_t\log\pi(a_t|s_t) \]

which is much easier to differentiate.

Reason 3: It connects naturally to likelihood optimization

\[ -\log \pi(a|s) \]

is already the familiar negative log-likelihood form used in classification.

REINFORCE simply weights it by the return:

\[ -G_t\log\pi(a_t|s_t) \]

We use \(\log \pi(a|s)\) because the logarithm lets us convert the derivative of a probability distribution into a sample-based gradient that is easy to estimate, while also turning products of trajectory probabilities into sums.

And mathematically, the most important identity is:

\[ \boxed{ \nabla_\theta \log \pi_\theta(a|s) = \frac{\nabla_\theta \pi_\theta(a|s)} {\pi_\theta(a|s)} } \]

That identity is really the doorway from expected return to the REINFORCE algorithm.

1.4.4.8 So, the Logarithm in REINFORCE Loss function

The logarithm gives us a convenient way to change the neural-network parameters so that the probability of the selected action increases or decreases.

The important gradient is:

\[ \nabla_\theta \log \pi_\theta(a_t|s_t) \]

This tells us:

Which direction should we change the network parameters to make the selected action more likely?

That interpretation is more important initially than the formal derivation.

1.4.4.9. What Does the Log Probability Look Like?

Because probabilities are between 0 and 1:

\[ 0<\pi(a|s)\leq1 \]

their logarithms are usually negative.

For example:

Probability Log probability
0.9 \(-0.105\)
0.7 \(-0.357\)
0.5 \(-0.693\)
0.2 \(-1.609\)
0.1 \(-2.303\)

Notice something important.

An action with probability:

\[ 0.1 \]

has a much more negative log probability than an action with probability:

\[ 0.9 \]

This helps learning strongly adjust unlikely actions when experience shows that they were actually useful.

1.4.4.10. Combine the Return and Log Probability

Now consider:

\[ G_t \log\pi_\theta(a_t|s_t) \]

The return tells us:

Was the action good or bad?

The log probability tells us:

How do we change the policy probability of that action?

Together:

\[ G_t \nabla_\theta \log\pi_\theta(a_t|s_t) \]

means approximately:

Change the policy in the direction that makes actions with good returns more likely.

This is the heart of REINFORCE.

1.4.4.11. A Simple Numerical Example

Suppose the agent chooses Right with:

\[ \pi(\text{Right}|s)=0.40 \]

Therefore:

\[ \log(0.40)\approx -0.916 \]

Suppose the return is:

\[ G_t=10 \]

Then:

\[ G_t\log\pi(a_t|s_t) = 10(-0.916) \]

\[ =-9.16 \]

But remember:

REINFORCE originally wants to maximize expected return.

Neural-network libraries such as PyTorch usually minimize a loss.

So we introduce a negative sign:

\[ L_t = -G_t \log\pi(a_t|s_t) \]

Therefore:

\[ L_t = -10(-0.916) \]

\[ =9.16 \]

Gradient descent tries to reduce this loss.

One way of reducing it is to make:

\[ \pi(\text{Right}|s) \]

larger.

So the probability of Right increases.

Exactly what we wanted.

1.4.4.12. Why the Negative Sign?

This is one of the most important things to explain.

The theoretical policy-gradient objective says:

maximize expected return.

We could write:

\[ J(\theta) = E[G] \]

and perform gradient ascent:

\[ \theta \leftarrow \theta+ \alpha\nabla_\theta J(\theta) \]

But PyTorch optimizers normally perform gradient descent:

\[ \theta \leftarrow \theta- \alpha\nabla_\theta L(\theta) \]

So instead of maximizing:

\[ G_t\log\pi_\theta(a_t|s_t) \]

we minimize its negative:

\[ \boxed{ L_t = -G_t \log\pi_\theta(a_t|s_t) } \]

The negative sign is mainly there because our optimizer minimizes losses while reinforcement learning wants to maximize rewards.

1.4.4.13. What Happens for a Good Action?

Suppose:

\[ G_t>0 \]

The action produced a good outcome.

Then minimizing

\[ -G_t\log\pi(a_t|s_t) \]

pushes:

\[ \pi(a_t|s_t) \]

up.

So:

Good return
    ↓
Positive G
    ↓
Increase probability
of selected action

In words:

That worked. Do more of it.

1.4.4.14. What Happens for a Bad Action?

Suppose:

\[ G_t<0 \]

Now the return is negative.

For example:

\[ G_t=-5 \]

Then:

\[ L_t = -(-5)\log\pi(a_t|s_t) \]

\[ = 5\log\pi(a_t|s_t) \]

Because the log probability is negative, gradient descent now pushes the selected action probability downward.

So:

Bad return
    ↓
Negative G
    ↓
Decrease probability
of selected action

In words:

That did not work. Do less of it.

1.4.4.15. The Most Important Intuition

Return Meaning Policy response
Large positive \(G_t\) Much better outcome Strongly increase action probability
Small positive \(G_t\) Slightly good outcome Slightly increase probability
\(G_t\approx0\) Little useful signal Little update
Negative \(G_t\) Poor outcome Decrease action probability

So the return acts like a weight.

We can think of the loss as:

\[ \boxed{ \text{Policy Loss} = -\text{Outcome Quality} \times \text{Log Probability of Action} } \]

or even more informally:

\[ \boxed{ \text{How good was it?} \times \text{Which action caused it?} } \]

1.4.4.16. Why Do We Sum Across the Episode?

An episode might contain:

s₀ → a₀
s₁ → a₁
s₂ → a₂
s₃ → a₃
...

Each selected action contributed to the eventual outcome.

Therefore REINFORCE computes:

\[ L = -\sum_t G_t \log \pi_\theta(a_t|s_t) \]

Each action gets its own return.

For example:

\[ G_0=20 \]

\[ G_1=18 \]

\[ G_2=10 \]

Then:

\[ L = -\left[ 20\log\pi(a_0|s_0) + 18\log\pi(a_1|s_1) + 10\log\pi(a_2|s_2) \right] \]

Actions early in the episode may receive credit for many future rewards.

1.4.4.17. A Small Episode Example

Suppose we have:

Step Selected action Probability Return
0 Right 0.60 8
1 Right 0.70 6
2 Left 0.40 2

The policy loss is:

\[ L = -\left[ 8\log(0.60) + 6\log(0.70) + 2\log(0.40) \right] \]

Approximately:

\[ \log(0.60)=-0.511 \]

\[ \log(0.70)=-0.357 \]

\[ \log(0.40)=-0.916 \]

Therefore:

\[ L = -\left[ 8(-0.511) + 6(-0.357) + 2(-0.916) \right] \]

\[ = -\left[ -4.088 -2.142 -1.832 \right] \]

\[ L \approx8.062 \]

The important point is:

Each log probability is weighted by how much future return followed that action.

1.4.4.18. In PyTorch

Suppose:

log_prob = distribution.log_prob(action)

and later:

policy_loss = -log_prob * G

That line corresponds directly to:

\[ L_t = -G_t \log\pi_\theta(a_t|s_t) \]

For an entire episode:

losses = []

for log_prob, G in zip(log_probs, returns):
    losses.append(-log_prob * G)

loss = torch.stack(losses).sum()

Then:

optimizer.zero_grad()
loss.backward()
optimizer.step()

1.4.4.19. What Does loss.backward() Actually Do Here?

You already know backpropagation, so connect it to something familiar.

When we call:

loss.backward()

PyTorch computes:

\[ \nabla_\theta L \]

The gradient flows:

Loss
 ↑
log probability
 ↑
action probabilities
 ↑
policy network
 ↑
weights θ

The optimizer then changes the policy-network weights.

Therefore:

optimizer.step()

eventually changes:

\[ \pi_\theta(a|s) \]

So the agent’s behavior changes.

1.4.4.20. A Useful Analogy: The Coach

Think of the policy as an athlete.

The athlete makes a decision:

“I will try Action A.”

Afterward, the coach sees the result.

Good outcome

Coach:

“That worked. You’re more likely to try that next time.”

Bad outcome

Coach:

“That didn’t work. Reduce your tendency to do that.”

The return \(G_t\) is the coach’s evaluation.

The log probability represents the behavior the athlete chose.

The policy loss combines them.

1.4.4.21. One Important Weakness

Suppose an action was good, but the episode happened to end poorly because of something much later.

REINFORCE may still assign a poor return to the earlier action.

This is part of the credit assignment problem.

It also contributes to high variance.

For example:

Action A
   ↓
good decision
   ↓
good decision
   ↓
bad random outcome
   ↓
poor episode return

REINFORCE may struggle to distinguish exactly which actions deserve credit.

That motivates the next topics:

\[ \text{Baseline} \]

\[ \text{Advantage} \]

and eventually:

\[ \text{Actor–Critic} \]

1.5. So, back to REINFORCE Loss

Let’s return to:

\[ \boxed{ L_{\text{REINFORCE}} = -\sum_t G_t \log\pi_\theta(a_t|s_t) } \]

Then let’s label every piece:

\[ \underbrace{-}_{\substack{\text{convert maximization}\\ \text{to minimization}}} \quad \underbrace{G_t}_{\substack{\text{How good}\\ \text{was the outcome?}}} \quad \underbrace{\log\pi_\theta(a_t|s_t)}_{\substack{\text{How likely was}\\ \text{the chosen action?}}} \]

And the complete interpretation is:

Change the policy so that actions followed by good returns become more likely, while actions followed by poor returns become less likely.

1.9 Final Takeaway

REINFORCE is essentially learning this rule:

             Selected Action
                    |
                    v
             How likely was it?
                    |
                 log π
                    |
                    ×
                    |
              Future Return
                   G
                    |
                    v
          Should I do this more
             or less often?
                    |
                    v
             Update Policy

Or in one sentence:

REINFORCE turns rewards into changes in behavior by using the return to decide whether the probability of a sampled action should go up or down.

1.10 The REINFORCE loss used in code

Because PyTorch minimizes losses, we usually write, as our goal in REINFORCE is maximizing return:

\[ L_{\text{policy}} = -G_t \log\pi_\theta(a_t|s_t) \]

For an entire episode:

\[ L_{\text{policy}} = -\sum_t G_t \log\pi_\theta(a_t|s_t) \]

1.11 A numerical reflection

Assume two actions:

\[ \pi(a_1|s)=0.2,\qquad \pi(a_2|s)=0.8 \]

The agent samples \(a_1\), and this eventually leads to a very good return.

  • Question: What should happen to \(P(a_1|s)\)?
  • Answer: It should increase.
  • Question: Should it immediately become 1.0?
  • Answer: No. Gradient descent makes incremental changes.

1.12 Problem with basic REINFORCE

Imagine three episodes:

Episode Return
1 72
2 19
3 103

All were generated using nearly the same policy.

The update can change considerably from episode to episode.

1.13 Why?

Because REINFORCE relies heavily on sampled returns.

A different trajectory can give a very different \(G_t\).

Therefore:

REINFORCE has high-variance gradient estimates.

This should be enough motivation to our next topic.

2. Introducing a Baseline

2.1 Introducing a Baseline

Suppose a student earns:

80 points on an exam.

Is 80 good?

  • It depends, right?

Suppose the class normally scores 50.

Then:

\[ 80-50=30 \]

The student performed considerably better than expected.

But suppose the class normally scores 95.

Then:

\[ 80-95=-15 \]

Now 80 was worse than expected.

2.2 Connection to reinforcement learning

REINFORCE asks:

“How much return did I receive?”

A better question is:

“How much better was the return than I expected?”

This motivates a baseline.

Instead of using:

\[ G_t \]

we use:

\[ G_t-b(s_t) \]

where \(b(s_t)\) represents an expected level of performance.

2.3 What should we use as the baseline?

A very natural choice is the state-value function:

\[ V(s_t) \]

Recall:

\[ V^\pi(s) = \mathbb E_\pi[G_t|S_t=s] \]

It means:

\(V(s)\) tells us how much future reward we normally expect when we are in state \(s\).

Therefore:

\[ G_t-V(s_t) \]

tells us:

How much better or worse did things turn out compared with what we expected from this state?

2.4 Numerical example

Suppose:

\[ V(s_t)=7 \]

and the actual return is:

\[ G_t=11 \]

Then:

\[ G_t-V(s_t)=4 \]

Interpretation:

The selected action produced an outcome better than expected.

Now suppose:

\[ G_t=4 \]

Then:

\[ G_t-V(s_t)=-3 \]

Interpretation:

The selected action performed worse than expected.

2.5 Important point

The baseline is not another reward.

It is a reference point.

A useful analogy is:

\[ \boxed{\text{Performance} - \text{Expectation}} \]

3. REINFORCE with a Baseline and the Advantage

3.1. REINFORCE with a Baseline and the Advantage

Now let’s modify the REINFORCE update.

Originally:

\[ \nabla_\theta J(\theta) \approx G_t \nabla_\theta \log\pi_\theta(a_t|s_t) \]

With a baseline:

\[ \nabla_\theta J(\theta) \approx \left(G_t-V(s_t)\right) \nabla_\theta \log\pi_\theta(a_t|s_t) \]

Define:

\[ A_t = G_t-V(s_t) \]

This is an advantage estimate.

3.2 What does “advantage” mean?

The general advantage function is:

\[ A(s,a) = Q(s,a)-V(s) \]

Recall the meanings:

Quantity Meaning
\(V(s)\) How good is this state?
\(Q(s,a)\) How good is this action in this state?
\(A(s,a)\) How much better is this action than what I normally expect?

A simple way to say it is:

Advantage measures whether an action was surprisingly good or surprisingly bad.

3.3 Example 1: Positive advantage

Suppose:

\[ V(s)=6 \]

and:

\[ Q(s,a)=10 \]

Then:

\[ A(s,a)=10-6=4 \]

So this action appears better than expected.

The actor should increase its probability.

3.4 Example 2: Negative advantage

Suppose:

\[ V(s)=9 \]

but:

\[ Q(s,a)=5 \]

Then:

\[ A(s,a)=5-9=-4 \]

This action appears worse than expected.

Its probability should decrease.

3.5 Example 3: Nearly zero advantage

Suppose:

\[ Q(s,a)=7.1 \]

and:

\[ V(s)=7 \]

Then:

\[ A(s,a)=0.1 \]

Nothing surprising happened.

Therefore the policy does not need a large update.

3.6 Why is this useful?

Consider two episodes that both receive a return of 10.

3.6.1 Situation A

\[ V(s)=2 \]

so:

\[ A=10-2=8 \]

Very good outcome.

3.6.2 Situation B

\[ V(s)=12 \]

so:

\[ A=10-12=-2 \]

The exact same return can mean something very different depending on expectation.

That is the key conceptual leap.

4. From REINFORCE to Actor–Critic

4.1 From REINFORCE to Actor–Critic

A natural question:

Where will \(V(s)\) come from?

We could somehow calculate it manually, but that becomes impossible for large state spaces.

Instead:

Let another neural network learn \(V(s)\).

Now we have two learners.

4.2 The Actor

The Actor learns:

\[ \pi_\theta(a|s) \]

Its job is:

Choose what to do.

Given the CartPole state:

\[ s= [x,\dot{x},\theta,\dot{\theta}] \]

the actor might output:

\[ [0.35,\;0.65] \]

and sample Left or Right.

4.3 The Critic

The Critic learns:

\[ V_w(s) \]

Its job is:

Evaluate how good the current situation is.

For example:

\[ V_w(s)=18.3 \]

can be interpreted approximately as:

“From this situation, I currently expect about 18 units of discounted future reward.”

4.5 What each component learns

4.5.1 Actor

Learns:

\[ \pi_\theta(a|s) \]

Question:

What should I do?

4.5.2 Critic

Learns:

Question:

Together:

The actor acts. The critic judges.

4.6 Relationship to earlier algorithms

Now that you have seen:

Q-learning

Primarily learns:

\[ Q(s,a) \]

and derives behavior from the values.

REINFORCE

Directly learns:

\[ \pi(a|s) \]

Actor–Critic

Learns both:

\[ \pi(a|s) \]

and:

\[ V(s) \]

So Actor–Critic combines ideas from value-based and policy-based reinforcement learning. (It’s a combined method)

5. TD Error

5.1 TD Error: How the Critic Gives Feedback

The remaining question is:

How does the critic know whether its prediction was good?

Recall the Bellman idea, from the Q-learning lecture:

\[ V(s_t) \approx r_t+\gamma V(s_{t+1}) \]

The critic predicted:

\[ V(s_t) \]

After taking an action, it obtains a new estimate:

\[ r_t+\gamma V(s_{t+1}) \]

Compare them:

\[ \boxed{ \delta_t = r_t+\gamma V(s_{t+1})-V(s_t) } \]

This is the temporal-difference error, or TD error.

5.1.1 Bellman Equation for State Value

Let’s start from the total discounted return:

\[ G_t = R_{t+1} +\gamma R_{t+2} +\gamma^2R_{t+3} +\gamma^3R_{t+4} +\cdots \]

The state-value function is defined as the expected return when we start in state \(s\) and follow policy \(\pi\):

\[ \boxed{ V^\pi(s) = \mathbb{E}_\pi[G_t\mid S_t=s] } \]

Now substitute the return formula:

\[ V^\pi(s) = \mathbb{E}_\pi \left[ R_{t+1} +\gamma R_{t+2} +\gamma^2R_{t+3} +\cdots \mid S_t=s \right] \]

Now factor out one \(\gamma\) from all future terms:

\[ V^\pi(s) = \mathbb{E}_\pi \left[ R_{t+1} + \gamma \left( R_{t+2} +\gamma R_{t+3} +\gamma^2R_{t+4} +\cdots \right) \mid S_t=s \right] \]

But notice that the quantity inside the parentheses is simply the return starting from the next time step:

\[ G_{t+1} = R_{t+2} +\gamma R_{t+3} +\gamma^2R_{t+4} +\cdots \]

Therefore,

\[ G_t = R_{t+1} + \gamma G_{t+1}. \]

Taking expectation:

\[ V^\pi(s) = \mathbb{E}_\pi \left[ R_{t+1} +\gamma G_{t+1} \mid S_t=s \right]. \]

Since

\[ \mathbb{E}_\pi[G_{t+1}\mid S_{t+1}] = V^\pi(S_{t+1}), \]

we obtain the Bellman equation for the state value:

\[ \boxed{ V^\pi(s) = \mathbb{E}_\pi \left[ R_{t+1} + \gamma V^\pi(S_{t+1}) \mid S_t=s \right] } \]

So, intuitively:

\[ \boxed{ \text{Value now} = \text{expected immediate reward} + \text{discounted expected value of the next state} } \]

If we write out the expectation over actions and next states explicitly:

\[ \boxed{ V^\pi(s) = \sum_a \pi(a|s) \sum_{s',r} p(s',r|s,a) \left[ r+\gamma V^\pi(s') \right] } \]

This is the full Bellman expectation equation for \(V^\pi(s)\).

But, since we are working on the sample-based version of the Bellman equation.

The exact Bellman expectation equation is:

\[ V^\pi(s_t) = \mathbb{E}_\pi \left[ r_t+\gamma V^\pi(s_{t+1}) \mid s_t \right] \]

if we use the convention that \(r_t\) is the reward received after taking the action at time \(t\).

But during actual interaction with the environment, we do not observe the expectation. We observe just one sample transition:

\[ s_t \rightarrow a_t \rightarrow r_t \rightarrow s_{t+1}. \]

So we use

\[ \boxed{ r_t+\gamma V(s_{t+1}) } \]

as a sample estimate of the expected quantity. Hence,

\[ \boxed{ V(s_t) \approx r_t+\gamma V(s_{t+1}) } \]

The right-hand side is often called the TD target:

\[ \boxed{ \text{TD target} = r_t+\gamma V(s_{t+1}) } \]

and we compare it with the critic’s current prediction:

\[ V(s_t). \]

That gives the TD error:

\[ \boxed{ \delta_t = \underbrace{r_t+\gamma V(s_{t+1})}_{\text{new sample-based target}} - \underbrace{V(s_t)}_{\text{current prediction}} } \]

The distinction is:

\[ \boxed{ V(s_t)= \mathbb E[r_t+\gamma V(s_{t+1})] } \]

is the Bellman equation, whereas

\[ \boxed{ V(s_t)\approx r_t+\gamma V(s_{t+1}) } \]

is what we can use from one observed experience, that is from one sampled experience.

5.2 Intuition

Think of:

\[ \delta_t = \text{what actually seems to be happening} - \text{what I expected} \]

5.3 Example 1: Better than expected

Suppose:

\[ r_t=2 \]

\[ \gamma=0.9 \]

\[ V(s_{t+1})=10 \]

and:

\[ V(s_t)=8 \]

Then:

\[ \delta_t = 2+0.9(10)-8 \]

\[ =2+9-8 \]

\[ =3 \]

Positive TD error:

Things turned out better than expected.

The actor should tend to make the selected action more likely.

5.4 Example 2: Worse than expected

Suppose:

\[ r_t=1,\qquad \gamma=0.9 \]

\[ V(s_{t+1})=4 \]

\[ V(s_t)=7 \]

Then:

\[ \delta_t = 1+0.9(4)-7 \]

\[ =1+3.6-7 \]

\[ =-2.4 \]

Negative TD error:

Things turned out worse than expected.

The actor should tend to reduce the probability of the selected action.

5.5 Why TD error is particularly useful

REINFORCE often waits for the episode’s return.

Actor–Critic can instead learn incrementally from:

\[ (s_t,a_t,r_t,s_{t+1}) \]

using:

\[ \delta_t = r_t+\gamma V(s_{t+1})-V(s_t) \]

This introduces bootstrapping.

The critic uses its estimate of the next state to improve its estimate of the current state.

5.6 Actor update

Use TD error as an advantage estimate:

\[ A_t\approx\delta_t \]

Then:

\[ \nabla_\theta J \approx \delta_t \nabla_\theta \log\pi_\theta(a_t|s_t) \]

The corresponding loss is:

\[ L_{\text{actor}} = -\delta_t \log\pi_\theta(a_t|s_t) \]

In implementation, \(\delta_t\) should normally be detached when used in the actor loss so the actor update does not unintentionally update the critic through that term.

5.7 Critic update

The critic wants:

\[ V(s_t) \]

to move toward:

\[ r_t+\gamma V(s_{t+1}) \]

So a simple critic loss is:

\[ L_{\text{critic}} = \delta_t^2 \]

or:

\[ L_{\text{critic}} = \frac12\delta_t^2 \]

5.8 Combined loss

One simple implementation is:

\[ L = L_{\text{actor}} + \lambda L_{\text{critic}} \]

where \(\lambda\) controls the contribution of the critic loss.

For an introductory implementation, setting:

\[ \lambda=0.5 \]

is reasonable.

We can share the first hidden layer.

class ActorCritic(nn.Module):
    def __init__(self, state_dim, action_dim):
        super().__init__()

        self.shared = nn.Sequential(
            nn.Linear(state_dim, 128),
            nn.ReLU()
        )

        # Actor head
        self.actor = nn.Linear(128, action_dim)

        # Critic head
        self.critic = nn.Linear(128, 1)

    def forward(self, state):
        x = self.shared(state)

        action_logits = self.actor(x)
        state_value = self.critic(x)

        return action_logits, state_value

def select_action(state):
    state = torch.tensor(
        state,
        dtype=torch.float32
    ).unsqueeze(0)

    logits, value = model(state)

6.7 One interaction with the environment

state, info = env.reset()

Now we know:

\[ s_t,\quad a_t,\quad r_t,\quad s_{t+1} \]

6.8 Calculate the TD target

First estimate:

\[ V(s_{t+1}) \]

next_state_tensor = torch.tensor(
    next_state,
    dtype=torch.float32
).unsqueeze(0)

with torch.no_grad():
    _, next_value = model(next_state_tensor)

next_value = next_value.squeeze()

For a true terminal state:

if terminated:
    next_value = torch.tensor(0.0)

Then:

gamma = 0.99

td_target = reward + gamma * next_value

Conceptually:

\[ \text{TD target} = r_t+\gamma V(s_{t+1}) \]

When the MDP truly terminates, there is no future value.

Gymnasium distinguishes true terminated states from time-limit truncated states specifically because that distinction matters for bootstrapping.

6.9 Calculate TD error

td_error = td_target - value

which is:

\[ \delta_t = r_t+\gamma V(s_{t+1})-V(s_t) \]

6.10 Actor loss

actor_loss = -log_prob * td_error.detach()

The .detach() is important.

We want the TD error to tell the actor:

“Increase or decrease this action’s probability.”

But we do not want the actor loss to change the critic through the TD-error computation.

6.11 Critic loss

critic_loss = td_error.pow(2)

The critic is trying to make:

\[ V(s_t) \]

closer to:

\[ r_t+\gamma V(s_{t+1}) \]

6.12 Combine the losses

loss = actor_loss + 0.5 * critic_loss

Then train:

optimizer.zero_grad()
loss.backward()
optimizer.step()

7.1 The complete program

import gymnasium as gym
import numpy as np
import torch
import torch.nn as nn
import torch.optim as optim

from torch.distributions import Categorical
import matplotlib.pyplot as plt

from safetensors.torch import save_file, load_file
from pathlib import Path

# List of few hyperparameters
gamma = 0.99
critic_weight = 0.5
num_episodes = 600 # Run at least 20 episodes please
learning_rate = 0.001

model_name = f"ActorCritic-lr={learning_rate}+ep={num_episodes}"
model_save_dir = f"./saved_models/"
model_file = f"{model_save_dir}/{model_name}.safetensors"

try:
    # Creates the directory; ignores the error if it already exists
    Path(model_save_dir).mkdir(parents=True, exist_ok=True)
except:
    print(f'Error: mkdir {model_save_dir} failed.')

# Reproducibility seed
seed = 42

torch.manual_seed(seed)
np.random.seed(seed)


# Environment
env = gym.make("CartPole-v1")

state_dim = env.observation_space.shape[0]
action_dim = env.action_space.n


# Actor-Critic Network
class ActorCritic(nn.Module):

    def __init__(self, state_dim, action_dim):
        super().__init__()

        self.shared = nn.Sequential(
            nn.Linear(state_dim, 128),
            nn.ReLU()
        )

        self.actor = nn.Linear(
            128,
            action_dim
        )

        self.critic = nn.Linear(
            128,
            1
        )


    def forward(self, state):

        x = self.shared(state)

        logits = self.actor(x)

        value = self.critic(x)

        return logits, value


# Create the model object
model = ActorCritic(
    state_dim,
    action_dim
)

# Select gradient descent optimizer variant: Adam optimizer
optimizer = optim.Adam(
    model.parameters(),
    lr=learning_rate
)



# Action Selection
def select_action(state):

    state_tensor = torch.tensor(
        state,
        dtype=torch.float32
    ).unsqueeze(0)

    logits, value = model(state_tensor)

    distribution = Categorical(
        logits=logits
    )

    action = distribution.sample()

    log_prob = distribution.log_prob(
        action
    )

    return (
        action.item(),
        log_prob.squeeze(),
        value.squeeze()
    )

# Training loop that runs for `num_episodes`
episode_rewards = []

for episode in range(num_episodes):

    if episode == 0:
        state, info = env.reset(seed=seed)
    else:
        state, info = env.reset()

    total_reward = 0

    while True:

        # Actor chooses action
        action, log_prob, value = \
            select_action(state)


        # Environment transition
        next_state, reward, \
        terminated, truncated, info = \
            env.step(action)

        done = terminated or truncated


        # Critic evaluates next state
        next_state_tensor = torch.tensor(
            next_state,
            dtype=torch.float32
        ).unsqueeze(0)

        with torch.no_grad():

            _, next_value = model(
                next_state_tensor
            )

            next_value = \
                next_value.squeeze()


        # No future reward after TRUE termination
        if terminated:
            next_value = torch.tensor(0.0)


        # TD Target
        reward_tensor = torch.tensor(
            reward,
            dtype=torch.float32
        )

        td_target = (
            reward_tensor
            + gamma * next_value
        )


        # TD Error
        td_error = (
            td_target - value
        )


        # Actor Loss
        actor_loss = (
            -log_prob
            * td_error.detach()
        )


        # Critic Loss

        critic_loss = \
            td_error.pow(2)


        # Total Loss

        loss = (
            actor_loss
            + critic_weight
            * critic_loss
        )


        # Backpropagation
        optimizer.zero_grad()

        loss.backward()

        optimizer.step()


        # Move forward
        state = next_state

        total_reward += reward


        if done:
            break


    episode_rewards.append(
        total_reward
    )


    if (episode + 1) % 20 == 0:

        avg_reward = np.mean(
            episode_rewards[-20:]
        )

        print(
            f"Episode {episode+1:4d} | "
            f"Reward: {total_reward:6.1f} | "
            f"Average(20): {avg_reward:6.1f}"
        )

print('Training completed.')


env.close()


# Now, save the trained agent's model weights
save_file(model.state_dict(), f"{model_file}")

7.3 Putting the Entire Algorithm Together

8. REINFORCE vs. Actor–Critic

8.1 REINFORCE vs. Actor-Critic

REINFORCE Actor–Critic
Learns policy Learns policy + value
Policy only Actor + Critic
Uses Monte Carlo return Can use TD error
Often waits for trajectory information Can update step-by-step
Higher variance Usually lower-variance feedback
No learned critic required Critic learns \(V(s)\)
\(G_t\) guides actor TD error/advantage guides actor

The important conceptual progression is:

\[ \boxed{ \text{REINFORCE} \rightarrow \text{REINFORCE + Baseline} \rightarrow \text{Advantage} \rightarrow \text{Actor–Critic} } \]

9. Some Reflections

9.1 Reflections

  • Qestion-1: Why might a return of 10 be good in one state but disappointing in another?
  • Answer 1: A return of 10 is only meaningful relative to what was expected in that state. If \(V(s)=5\), then 10 is good; if \(V(s)=15\), then 10 is disappointing.
  • Question-2: What information does \(V(s)\) give us that the raw reward does not?
  • Answer 2: \(V(s)\) tells us the expected future return from state \(s\). A raw reward only tells us what happened immediately at one step.
  • Question-3: If \(\delta_t>0\), what does that tell the actor?
  • Answer-3: the outcome was better than expected. The actor should increase the probability of the action it took.
  • Queston-4: If \(\delta_t<0\), what does that tell the actor?
  • Answer-4: the outcome was worse than expected. The actor should decrease the probability of the selected action.
  • Question-5: Why do we need .detach() in: actor_loss = -log_prob * td_error.detach() ?
  • Answer-5: We use .detach() so the TD error acts only as a feedback signal for the actor. Without it, gradients from actor_loss could also flow back through the critic’s value estimate and unintentionally update the critic through the actor loss.
  • Question-6: What is the main conceptual difference between REINFORCE and Actor–Critic?
  • Answer-6: REINFORCE learns only the policy and usually uses sampled episode returns. On the other hand, Actor–Critic learns both a policy and a value function, with the critic providing more immediate feedback to the actor.

9.3 Final takeaway

The Actor learns what to do. The Critic learns how good things are. The TD error tells the Actor whether an action worked better or worse than expected.
