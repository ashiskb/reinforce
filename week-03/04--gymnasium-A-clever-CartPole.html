We will take a peek at our first RL algorithm: Q-learning

  • Q-learning is an immediate next step towards improving our random policy agent.
    • A random policy agent, like ours picks an actions, \(a\) randomly:
action = env.action_space.sample()

  • If you missed how we built the random policy agent, please go watch previous lecture.

  • While, a Q-learning based trained agent, standing at state, \(s\) would pick the action, \(a\) that maximizes \(Q(s,a)\) value. In other words: policy to take an action \(a\) at state \(s\) is \(\pi(s) = \underset{a}{\text{arg max}}\quad Q(s,a)\):

    • Please note,
      • \(s_i\) is one of the observed state from the set of Observation Space, \(S = \{s_1, s_2, \cdots, s_m\}\).
      • \(a_i\) is one of the action from the set of Action space, \(A = \{a_1, a_2, \cdots, a_m\}\).
    • So, the Q-table is a simple lookup matrix to store the expected future rewards, called the Q-values, for every possible action, \(a_j\) in every possible state, \(s_i\).
    • The structure of a \(Q(s,a)\) table looks like below:
\(Q\)-table \(a_1\) \(a_2\) \(\cdot\) \(a_n\)
\(s_1\) \(Q(s_1,a_1)\) \(Q(s_1,a_2)\) \(\cdots\) \(Q(s_1,a_n)\)
\(s_2\) \(Q(s_2,a_1)\) \(Q(s_2,a_2)\) \(\cdots\) \(Q(s_2,a_n)\)
\(s_3\) \(Q(s_3,a_1)\) \(Q(s_3,a_2)\) \(\cdots\) \(Q(s_3,a_n)\)
\(s_4\) \(Q(s_4,a_1)\) \(Q(s_4,a_2)\) \(\cdots\) \(Q(s_4,a_n)\)
\(\vdots\) \(\vdots\) \(\vdots\) \(\cdots\) \(\vdots\)
\(s_m\) \(Q(s_m,a_1)\) \(Q(s_m,a_2)\) \(\cdots\) \(Q(s_m,a_n)\)
  • Training the RL agent with Q-learning means updating the \(Q\) table such that the total reward is maximized.

A refresher: Reinforcement Learning in one picture

In reinforcement learning, an agent repeatedly interacts with an environment:

\[ \boxed{ \text{State }s_t \rightarrow \text{Action }a_t \rightarrow \text{Reward }r_{t+1} \rightarrow \text{New State }s_{t+1} } \]

For CartPole:

  • Agent: our Python program
  • Environment: CartPole-v1
  • State: position and motion (velocity + angle) of the cart and pole
  • Action: push cart left or right
  • Reward: +1 for every timestep the pole remains balanced
  • Goal: keep collecting reward for as long as possible

The interesting part is that we do not tell the agent exactly how to balance the pole. We let it learn which actions tend to produce good future outcomes.

Markov Decision Process — the RL framework

Let’s try to answer the following question:

What information does the agent need in order to learn from its interaction with CartPole?

A Markov Decision Process (MDP) is simply a way to describe the repeated interaction between an agent and an environment.

At each step:

\[ \boxed{ \text{State} \rightarrow \text{Action} \rightarrow \text{Reward + Next State} } \]

For CartPole:

  • State \(s_t\): What does the environment look like right now?
  • Action \(a_t\): What should the agent do?
  • Reward \(r_{t+1}\): How good was that action?
  • Next state \(s_{t+1}\): What happened after the action?

So one interaction looks like:

\[ s_t \overset{a_t}{\longrightarrow} (r_{t+1},s_{t+1}) \]

In our Python code, this happens here:

next_observation, reward, terminated, truncated, info = env.step(action)

The agent gives Gymnasium an action, and the environment returns the next state and reward.

What is the state in CartPole?

The state contains four pieces of information:

\[ s_t = [ \text{cart position}, \text{cart velocity}, \text{pole angle}, \text{pole angular velocity} ] \]

For example:

[-0.03, 0.18, 0.04, -0.29]

We can think of this simply as:

“Here is the current situation of the cart and pole.”

What are the actions?

The agent has only two choices:

\[ a_t \in \{0,1\} \]

corresponding to pushing the cart in one direction or the other.

The important question for the agent therefore becomes:

Given the current state, should I push left or right?

What is the reward?

CartPole gives the agent a reward for keeping the pole balanced.

Therefore, the agent gradually learns:

Which actions, in which situations, tend to keep the pole balanced longer?

This is exactly what our Q-values will eventually represent.

Why is it called “Markov”?

For now, we only need one simple intuition:

The agent makes its decision based on the current state.

The current CartPole state contains the information we need about where the cart is, how it is moving, where the pole is pointing, and how it is moving.

We therefore treat the current state as sufficient for deciding what to do next.

We will return to the formal meaning of the Markov property later.

Our RL interaction loop

The CartPole program can now be viewed as:

\[ \boxed{ s_t \rightarrow a_t \rightarrow r_{t+1},s_{t+1} \rightarrow a_{t+1} \rightarrow \cdots } \]

In code:

observation, info = env.reset()

Initially, our agent chooses actions randomly:

action = env.action_space.sample()

It interacts with the MDP, but it does not learn anything from the experience.

Our next step is to change that.

We want the agent to remember whether an action taken in a particular state turned out to be useful:

\[ \boxed{ \text{State} + \text{Action} + \text{Reward} + \text{Next State} \quad\Longrightarrow\quad \text{Learning} } \]

That takes us directly to Q-learning, the algorithm we will learn today.

For this first CartPole walkthrough, we just need only this mental model:

\[ \boxed{ \text{See the situation} \rightarrow \text{Take an action} \rightarrow \text{See what happened} \rightarrow \text{Learn from it} } \]

Markov Decision Process – the RL framework

Many RL problems are represented as a Markov Decision Process (MDP):

\[ \boxed{(S,A,P,R,\gamma)} \]

where:

\[ S=\text{set of states} \]

\[ A=\text{set of actions} \]

\[ P(s'|s,a)=\text{probability of reaching }s' \]

\[ R(s,a)=\text{reward} \]

and

\[ \gamma=\text{discount factor}. \]

For CartPole, a state contains four numbers:

\[ s = [x,\dot{x},\theta,\dot{\theta}] \]

representing roughly:

  1. cart position,
  2. cart velocity,
  3. pole angle,
  4. pole angular velocity

The action space is much simpler:

\[ A=\{0,1\}, \]

where one action pushes left and the other pushes right.

In the code:

observation, reward, terminated, truncated, info = env.step(action)

Gymnasium is essentially giving us one MDP transition:

\[ (s_t,a_t,r_{t+1},s_{t+1}). \]

What does the agent actually want?

The agent does not necessarily want the largest immediate reward.

It wants to maximize its accumulated future reward, called the return, \(G_t\):

\[ G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \gamma^3 r_{t+4} +\cdots \]

or:

\[ \boxed{ G_t=\sum_{k=0}^{\infty}\gamma^k r_{t+k+1} } \]

The parameter

\[ 0\leq\gamma\leq1 \]

is the discount factor:

  • If \(\gamma=0\), the agent cares almost entirely about the immediate reward.
  • If \(\gamma\approx1\), the agent cares strongly about long-term consequences.

In clever CartPole code, we set:

gamma = 0.99

that means:

“Don’t just keep the pole balanced for the next instant. Prefer actions that are likely to keep it balanced for a long time.”

What is \(Q(s,a)\)?

\(Q\)-table \(a_1\) \(a_2\) \(\cdot\) \(a_n\)
\(s_1\) \(Q(s_1,a_1)\) \(Q(s_1,a_2)\) \(\cdots\) \(Q(s_1,a_n)\)
\(s_2\) \(Q(s_2,a_1)\) \(Q(s_2,a_2)\) \(\cdots\) \(Q(s_2,a_n)\)
\(s_3\) \(Q(s_3,a_1)\) \(Q(s_3,a_2)\) \(\cdots\) \(Q(s_3,a_n)\)
\(s_4\) \(Q(s_4,a_1)\) \(Q(s_4,a_2)\) \(\cdots\) \(Q(s_4,a_n)\)
\(\vdots\) \(\vdots\) \(\vdots\) \(\cdots\) \(\vdots\)
\(s_m\) \(Q(s_m,a_1)\) \(Q(s_m,a_2)\) \(\cdots\) \(Q(s_m,a_n)\)

The central question for our agent is:

If I am in state \(s\), how good would it be to take action \(a\)?

We represent this using the action-value function:

\[ \boxed{Q(s,a)} \]

Think of it as the agent’s current estimate of the long-term usefulness of taking action \(a\) in state \(s\) (a type of Quality score if you would like to connect \(Q\) to a meaningful word).

Suppose hypothetically:

\[ Q(s,\text{Left})=14.2 \]

and

\[ Q(s,\text{Right})=28.7. \]

If the agent trusts what it has learned so far, it should choose:

\[ \text{Right}. \]

That is exactly what this code does:

action = np.argmax(Q[state])

But initially the agent knows nothing

At the beginning:

Q = np.zeros(...)

so essentially:

\[ Q(s,a)=0 \]

for everything.

The agent therefore has a problem:

How can it know which action is best when it has never tried anything?

It has to explore.

This leads to one of the most important ideas in RL:

\[ \boxed{\text{Exploration vs. Exploitation}} \]

Exploration: try something, perhaps randomly, to learn more.

Exploitation: use what you already know and choose the currently best action.

The \(\epsilon\)-greedy policy

A very simple way to balance these is the epsilon-greedy policy.

  • With probability \(\epsilon\), take a random action.
  • With probability \(1-\epsilon\), take the best action we currently know.

Our code says:

if np.random.random() < epsilon:
    action = env.action_space.sample()   # explore
else:
    action = np.argmax(Q[state])         # exploit

So early in training we might use:

\[ \epsilon=1.0. \]

The agent behaves almost completely randomly.

Later, we gradually / smoothly decrease \(\epsilon\) to a minimum \(\epsilon=0.05\). At that time, approximately 5% exploration and 95% exploitation.

The goal of decreasing \(\epsilon\) is to:

Explore a lot at the beginning, then gradually explore less as you gain experience.

For our code,

epsilon = (
    epsilon_end
    + (epsilon_start - epsilon_end)
    * np.exp(-episode / epsilon_decay)
)

the mathematical form is

\[ \boxed{ \epsilon_k = \epsilon_{\min} + (\epsilon_{\max}-\epsilon_{\min}) e^{-k/\tau} } \]

where \(k\) is the current episode number and \(\tau\) is epsilon_decay.

With our values set to:

epsilon_start = 1.0
epsilon_end   = 0.05
epsilon_decay = 1000

we get

\[ \boxed{ \epsilon = 0.05 + 0.95e^{-\text{episode}/1000} } \]

Start with

\[ \epsilon_{\text{start}}=1.0. \]

At the beginning, the agent knows nothing. So we want substantial exploration.

The quantity

\[ \epsilon_{\text{start}}-\epsilon_{\text{end}} = 1.0-0.05 = 0.95 \]

is the amount of epsilon that we allow to decay away.

The exponential term

\[ e^{-\text{episode}/1000} \]

starts at \(1\) and gradually approaches \(0\).

So:

\[ 0.95e^{-\text{episode}/1000} \]

gradually disappears, leaving only

\[ \epsilon_{\text{end}}=0.05. \]

Episode 0: almost entirely exploration

At episode 0,

\[ e^{-0/1000}=1. \]

Therefore,

\[ \epsilon = 0.05+0.95(1) = 1.0. \]

So:

if np.random.random() < epsilon:

is essentially always true.

The agent behaves randomly:

\[ \boxed{\epsilon=1.0 \Rightarrow 100\%\text{ exploration}} \]

This makes sense—the agent hasn’t learned anything yet.

Episode 1000

Now:

\[ \epsilon = 0.05+0.95e^{-1}. \]

Since

\[ e^{-1}\approx0.368, \]

we get

\[ \epsilon \approx 0.05+0.95(0.368) \approx0.40. \]

So around episode 1000:

\[ \boxed{\epsilon\approx0.40} \]

meaning roughly:

  • 40% chance: explore
  • 60% chance: exploit what has been learned

Episode 2000

\[ \epsilon = 0.05+0.95e^{-2} \approx0.179. \]

So the agent now explores only about 18% of the time.

Episode 5000

\[ \epsilon = 0.05+0.95e^{-5} \approx0.056. \]

The agent is now very close to the desired minimum:

\[ \boxed{\epsilon_{\text{end}}=0.05} \]

so it uses its learned policy about 95% of the time but still occasionally tries something different.

In Summary:

Episode Approx. \(\epsilon\) Behavior
0 1.00 Almost completely exploring
500 0.63 More exploration than exploitation
1000 0.40 Increasingly trusts learned Q-values
2000 0.18 Mostly exploiting
3000 0.10 Strongly exploiting
5000 0.056 Almost at minimum exploration

What does epsilon_decay = 1000 actually mean?

This is an important subtlety.

It does not mean epsilon reaches 0.05 after 1000 episodes.

Instead, 1000 controls how quickly it moves toward 0.05.

After one decay period—1000 episodes—the decaying portion has fallen to about

\[ e^{-1}=36.8\% \]

of its original value.

So:

epsilon_decay = 500

would make exploration disappear more quickly, while

epsilon_decay = 3000

would keep the agent exploring for longer.

Why not simply set epsilon to zero eventually?

Because even a fairly well-trained agent may not have discovered everything.

Keeping

\[ \epsilon_{\text{end}}=0.05 \]

means:

95% of the time, do what you currently believe is best—but 5% of the time, remain curious.

This reinforces one of the central challenges in reinforcement learning:

\[ \boxed{\text{Exploration} \quad\text{vs.}\quad \text{Exploitation}} \]

Early in training:

\[ \text{Explore} \gg \text{Exploit} \]

Later:

\[ \text{Exploit} \gg \text{Explore}. \]

And the exponential epsilon-decay equation gives us a simple, smooth transition between those two behaviors.

Where does the actual learning happen?

This is the heart of Q-learning.

After taking action \(a\), suppose we observe:

\[ s,a,r,s'. \]

We update our estimate using:

\[ \boxed{ Q(s,a) \leftarrow Q(s,a) + \alpha \left[ r+\gamma\max_{a'}Q(s',a') - Q(s,a) \right] } \]

It looks intimidating at first, but its meaning is surprisingly intuitive.

Our old belief is:

\[ Q(s,a). \]

Our new evidence suggests that the action was worth approximately:

\[ r+\gamma\max_{a'}Q(s',a'). \]

So we calculate:

\[ \underbrace{ r+\gamma\max_{a'}Q(s',a') }_{\text{new target}} - \underbrace{Q(s,a)}_{\text{old estimate}}. \]

That difference is the TD error.

The agent is essentially saying:

“What happened was better or worse than I expected. Let me adjust my belief.”

What does \(\alpha\) do?

The parameter

\[ \alpha \]

is the learning rate.

In our code:

alpha = 0.1

The update can be viewed as:

\[ \text{new estimate} = \text{old estimate} + \alpha(\text{new information}). \]

If \(\alpha\) is very small, the agent learns slowly.

If \(\alpha\) is very large, it changes its beliefs aggressively.

So the three important parameters students should notice are:

\[ \boxed{ \alpha=\text{How quickly do I learn?} } \]

\[ \boxed{ \gamma=\text{How much do I care about the future?} } \]

\[ \boxed{ \epsilon=\text{How much should I explore?} } \]

A tiny numerical example

Suppose the agent currently believes:

\[ Q(s,a)=4. \]

It takes the action and receives:

\[ r=1. \]

In the next state:

\[ \max_{a'}Q(s',a')=6. \]

Let:

\[ \gamma=0.9,\qquad\alpha=0.1. \]

The target is:

\[ 1+0.9(6)=6.4. \]

The error is:

\[ 6.4-4=2.4. \]

Therefore:

\[ Q(s,a) \leftarrow 4+0.1(2.4) \]

\[ =4.24. \]

The agent has slightly increased its confidence that this was a good action.

It does this again and again and again over thousands of interactions.

That is learning.

Why did we discretize CartPole?

There is another important issue hiding in our code.

CartPole gives observations such as:

[-0.032, 0.187, 0.041, -0.296]

and then perhaps:

[-0.029, 0.381, 0.035, -0.575]

There are essentially an enormous number of possible continuous states.

But our Q-table wants something like:

Q[state, action]

So we group nearby continuous values into bins.

For example:

\[ \theta=0.031 \]

and

\[ \theta=0.033 \]

might be treated as the same discrete state.

This is a crude approximation—but pedagogically it gives us something very valuable:

\[ \boxed{ \text{continuous CartPole} \rightarrow \text{discrete states} \rightarrow \text{Q-table} } \]

Later in the course we will ask:

What if we don’t want to discretize?

And that question leads naturally to function approximation and Deep Q-Networks (DQN).

Instead of:

\[ Q\text{-table}, \]

we will eventually learn:

\[ \boxed{ Q(s,a;\theta) } \]

using a neural network.

That is one of the bridges from classical RL to Deep Reinforcement Learning.

Episode, termination, and reset

An episode represents one attempt by our agent.

For CartPole:

observation, info = env.reset()

starts a new episode.

The agent then repeatedly takes actions until:

terminated or truncated

becomes True.

Conceptually:

\[ s_0 \rightarrow a_0 \rightarrow r_1 \rightarrow s_1 \rightarrow a_1 \rightarrow r_2 \rightarrow\cdots \rightarrow\text{END}. \]

We then start another attempt.

The agent may fail quickly during early episodes:

Episode 1       → 18 steps
Episode 2       → 24 steps
Episode 3       → 15 steps

but after learning:

Episode 1000    → 183 steps
Episode 2000    → 347 steps
Episode 4000    → 500 steps

That growing episode reward is evidence that the policy is improving.

Now look again at the CartPole code

The entire program can now be mentally reduced to this:

Initialize Q

Repeat for many episodes:

    Observe state

    Repeat:

        Choose action
           ↓
        explore OR exploit

        Take action
           ↓
        observe reward + next state

        Learn
           ↓
        update Q(s,a)

        Move to next state

    until episode ends

Or mathematically:

\[ \boxed{ s_t \overset{\epsilon\text{-greedy}}{\longrightarrow} a_t \overset{\text{environment}}{\longrightarrow} (r_{t+1},s_{t+1}) \overset{\text{Q-update}}{\longrightarrow} \text{better }Q } \]

That is the key idea.

# [cart position,

num_bins = (6,  #cart position
            6,  #cart velocity
            12, #pole angle
            12) #pole angular velocity]

# Practical ranges used for discretization.
# Velocity dimensions are theoretically unbounded,
# so we choose reasonable clipping ranges.
lower_bounds = np.array([-2.4, -3.0, -0.21, -3.5])
upper_bounds = np.array([ 2.4,  3.0,  0.21,  3.5])

bins = [
    np.linspace(lower_bounds[i],
                upper_bounds[i],
                num_bins[i] - 1)
    for i in range(4)
]


def discretize(observation):
    """
    Convert the continuous observation into a discrete state.
    """

    state = tuple(
        #np.digitize returns index of the bin to which each observation value belongs
        np.digitize(observation[i], bins[i]) 
        for i in range(4)
    )

    return state

Q-learning hyperparameters

num_episodes = 500

alpha = 0.1       # learning rate
gamma = 0.99      # discount factor

epsilon_start = 1.0
epsilon_end = 0.05
epsilon_decay = 1000


episode_rewards = []

Training in the agent-environment loop

Training in the agent-environment loop

for episode in tqdm(range(num_episodes)):

    observation, info = env.reset()

    state = discretize(observation)

    terminated = False
    truncated = False

    total_reward = 0


    # Gradually reduce exploration
    epsilon = (
        epsilon_end
        + (epsilon_start - epsilon_end)
        * np.exp(-episode / epsilon_decay)
    )


    while not (terminated or truncated):

        # We will adopt the epsilon-greedy policy
        if np.random.random() < epsilon:

            # EXPLORE
            action = env.action_space.sample()

        else:

            # EXPLOIT what has been learned
            action = np.argmax(Q[state])


        # now, interact with environment with the selected action
        next_observation, reward, terminated, truncated, info = \
            env.step(action)

        next_state = discretize(next_observation)


        # -------------------------------------------------
        # Q-learning update:
        # Q(s,a) <- Q(s,a) + alpha *( target - Q(s,a) )
        # where,
        #     target = r + gamma * max Q(s',a')
        # -------------------------------------------------

        if terminated:
            target = reward
        else:
            target = reward + gamma * np.max(Q[next_state])


        Q[state + (action,)] += alpha * (target - Q[state + (action,)])


        state = next_state

        total_reward += reward


    episode_rewards.append(total_reward)


env.close()
print(f'Training complete!')

upper_bounds = np.array([ 2.4,  3.0,  0.21,  3.5])

bins = [
    np.linspace(lower_bounds[i],
                upper_bounds[i],
                num_bins[i] - 1)
    for i in range(4)
]


def discretize(observation):
    """
    this function converts the continuous observation into a discrete state.
    """

    state = tuple(
        #np.digitize returns index of the bin to which each observation value belongs
        np.digitize(observation[i], bins[i]) 
        for i in range(4)
    )

    return state


# 3. Initialize the Q-table
# Shape:
# state dimensions + number of actions
#
# 6 x 6 x 12 x 12 x 2

Q = np.zeros(num_bins + (env.action_space.n,))


# 4. Q-learning hyperparameters
num_episodes = 500

alpha = 0.1       # learning rate
gamma = 0.99      # discount factor

epsilon_start = 1.0
epsilon_end = 0.05
epsilon_decay = 1000


episode_rewards = []


# 5. Training
for episode in tqdm(range(num_episodes)):

    observation, info = env.reset()

    state = discretize(observation)

    terminated = False
    truncated = False

    total_reward = 0


    # Gradually reduce exploration
    epsilon = (
        epsilon_end
        + (epsilon_start - epsilon_end)
        * np.exp(-episode / epsilon_decay)
    )


    while not (terminated or truncated):

        # We will adopt the epsilon-greedy policy
        if np.random.random() < epsilon:

            # EXPLORE
            action = env.action_space.sample()

        else:

            # EXPLOIT what has been learned
            action = np.argmax(Q[state])


        # now, interact with environment with the selected action
        next_observation, reward, terminated, truncated, info = \
            env.step(action)

        next_state = discretize(next_observation)


        # -------------------------------------------------
        # Q-learning update:
        # Q(s,a) <- Q(s,a) + alpha *( target - Q(s,a) )
        # where,
        #     target = r + gamma * max Q(s',a')
        # -------------------------------------------------

        if terminated:
            target = reward
        else:
            target = reward + gamma * np.max(Q[next_state])


        Q[state + (action,)] += alpha * (target - Q[state + (action,)])


        state = next_state

        total_reward += reward


    episode_rewards.append(total_reward)


env.close()
print(f'Training complete!')


#Post-processing / Debugging
print(f'Debugging/post-processing begins...')

indices  = np.argwhere(Q != 0)
print(f'num of non-zero indices = {len(indices)}')
if len(indices)>0:
    print('first one: ',indices[0])

    # Q(s, action=1) = ?

## Also, save the model for later use

  • What constitutes the model of our agent?
    • The observation space discretizer
      • We are not saving in this particular example, as it is a globally defined function.
    • The \(Q\)-table
  • What to save as part of the model?
    1. The \(Q\)-table
  • We could use Python joblib or pickle to save the Q-table as a file via the joblib.dump(Q,'Q.joblib') or pickle.dump(Q,'Q.pkl').
    • But, we won’t be doing that.
    • The primary risk of using joblib and pickle in Python is arbitrary code execution, meaning that loading a tampered or untrusted file can silently run malicious code on your computer or server.
      • Joblib uses Python’s underlying pickle serialization model for many of its operations.
      • The pickle format does not just store static data; it can store instructions on how to reconstruct complex Python objects, including executable code.
      • When you call load() on a file, Python automatically executes any embedded instructions, giving an attacker full access to your system.
    • It’s not like we will be hiding malicious codes into our own joblib/pickle files, but essentially with this exercise, I encourage you to get a better habit in storing your model files in a safe, transparent, sharable manner.
      • The best alternative could be to switch to formats that only store raw numbers and metadata without executable support, such as Safetensors for tensors, or JSON and CSV/tsv for basic data.
      • In this exercise, we are saving the model, Q-table, which is a numpy.ndarray object as JSON file.

Some unresolved questions to follow-up with next

Why does the Bellman equation justify our Q-learning update?

Why should learning from the best future Q-value work?

How should we choose \(\alpha\), \(\gamma\), and \(\epsilon\)?

Is \(\epsilon\)-greedy really the best way to explore?

What happens when the state space has millions—or infinitely many—states?

Can we replace the Q-table with a neural network?

Why can deep Q-learning sometimes become unstable?

What if actions themselves are continuous?

What if rewards arrive only much later?

Those are not problems with this example—they are exactly the questions that motivate the next several lectures in reinforcement learning.

So I would frame the CartPole notebook not as “Now you know Q-learning,” but as:

We have just built our first agent that actually learns from experience. Now we need to understand why it works, when it fails, and how to make it much more powerful.
